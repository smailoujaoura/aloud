Your own speech server

Let another computer do the talking.

Aloud makes its voices inside your browser. On an older laptop or a phone that can be slow: the voice stops to catch up, or the richer voices are out of reach. If you have a faster machine somewhere, a desktop at home, a gaming PC, or a small server online, it can make the speech instead. Aloud sends it each sentence, plays what comes back, and highlights along as usual.

The short version. Start a speech server with one Docker command. Then in Aloud open Settings → Voice → Custom, enter the server's address, press Connect, and press Use on one of its voices.

Which server?

Aloud works with servers that offer OpenAI's speech API. Three good ones:

Kokoro on a graphics card

Kokoro-FastAPI on an NVIDIA card. Aloud's richest voices, many times faster than speech. The best choice if you have a gaming PC.

Kokoro on a processor

The same server without a graphics card. Works on any recent PC; a strong desktop keeps up, a small server may not.

Phonon on a processor

Gradium's own server for Phonon. Fast without a graphics card, so a modest home PC or a cheap server is enough. One language per server. The model is for non-commercial use only.

What it costs you

Nothing from Aloud: it is your machine. Text you read goes to that machine and nowhere else. A server at home needs to be on while you read.

1. Install Docker

On Windows and macOS, install Docker Desktop. On Linux, install Docker Engine from your distribution or Docker's guide.

For Kokoro on a graphics card you also need the NVIDIA driver, and on Linux the NVIDIA Container Toolkit. On Windows, Docker Desktop with WSL 2 passes the card through by itself.

2. Start the server

Pick one, and paste it into a terminal (PowerShell on Windows). The first start downloads the voice model, so give it a minute or two.

Kokoro on a graphics card NVIDIA 
docker run -d --name kokoro --restart unless-stopped --gpus all -p 8880:8880 ghcr.io/remsky/kokoro-fastapi-gpu:v0.9.2
Kokoro on a processor any PC 
docker run -d --name kokoro --restart unless-stopped -p 8880:8880 ghcr.io/remsky/kokoro-fastapi-cpu:v0.9.2
Phonon on a processor by Gradium 
docker run -d --name phonon --restart unless-stopped -p 8880:8880 \
  -e PTTS_LANG=en -e PTTS_QUANT=q8 \
  -e PTTS_MODEL=hf://smailoujaoura/phonon-40m-multilingual@514a70f83654b3a81844cc01bbe5438254080433 \
  ghcr.io/gradium-ai/ptts-openai-server:0.6.0

This is the same model as Aloud's built-in Phonon, from Aloud's mirror of Gradium's. PTTS_LANG sets the language it reads: en, fr, de, es or pt. For a second language, start a second server with another name and port, such as --name phonon-fr -p 8881:8880 -e PTTS_LANG=fr. On Windows PowerShell, put it all on one line without the backslashes. Is it running? On the same computer, open http://localhost:8880/v1/audio/voices in a browser. You should see a list of voice names. If the page does not load yet, the model is still downloading: docker logs -f kokoro (or phonon) shows how far it has got.

3. Connect Aloud

  1. Open Aloud's Settings → Voice and choose the Custom tab.
  2. Address: http://localhost:8880/v1 if the server is on this computer. For one on another machine, see below.
  3. Model and Key: leave both empty for a server at home.
  4. Press Connect. Your browser asks for permission to reach that address, and Firefox also asks whether Aloud may send it page content. Allow both: that is the text being read, and it goes to this address only.
  5. It says Connected and lists the voices. Press Use on one, open an article, and press play.

Every speed works. A server that only reads at normal speed (Phonon's) is asked for 1×, and Aloud speeds the audio up itself.

Languages. Aloud tells which language a server voice speaks from its name. Kokoro's names start with it: af_heart is American English, bf_emma British, ff_siwis French, ef_dora Spanish. Any other name is taken to be English. On a page in a language your server voice doesn't speak, Aloud reads with a voice on your device for that language, as usual.

From your phone or another computer

On the same Wi-Fi

Use the server computer's address on your network, such as http://192.168.1.20:8880/v1. On Windows, ipconfig shows it (IPv4 Address); on macOS and Linux, your network settings do. If your firewall asks, allow Docker on private networks. Aloud accepts plain http:// for addresses on your own network.

Anywhere, privately

Install Tailscale on the server and on your phone or laptop, signed in to the same account. Then use the server's Tailscale name, such as http://my-pc.your-tailnet.ts.net:8880/v1, or its 100.x.y.z address. Tailscale encrypts the connection, and nothing is open to the internet.

On the internet, with a key

For a server you rent, with a domain name. It has to be reached over https://, and it should ask for a key so strangers cannot use it. This assumes nginx and a certificate (from Certbot, or Cloudflare's origin certificate if your domain is on Cloudflare).

  1. Start the server as above, but only for nginx on the same machine: change -p 8880:8880 to -p 127.0.0.1:8880:8880.
  2. Make a key, and keep it somewhere safe: 
    openssl rand -hex 32
  3. Create the site in nginx, with your domain, certificate paths and key: 
    # /etc/nginx/sites-available/tts.example.com
map $http_authorization $tts_key_ok {
    default                      0;
    "Bearer PASTE_YOUR_KEY_HERE" 1;
}

server {
    listen 443 ssl;
    listen [::]:443 ssl;
    server_name tts.example.com;

    ssl_certificate     /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;

    client_max_body_size 64k;
    access_log off;

    location /v1/ {
        add_header Access-Control-Allow-Origin  "*" always;
        add_header Access-Control-Allow-Headers "Authorization, Content-Type" always;
        add_header Access-Control-Allow-Methods "GET, POST, OPTIONS" always;
        if ($request_method = OPTIONS) { return 204; }
        if ($tts_key_ok = 0)           { return 401; }
        proxy_pass http://127.0.0.1:8880;
        proxy_http_version 1.1;
        proxy_buffering off;
        proxy_read_timeout 120s;
    }

    location / { return 404; }
}
    Then turn it on and reload: 
    sudo ln -s /etc/nginx/sites-available/tts.example.com /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
    If nginx -t asks you to increase map_hash_bucket_size, add map_hash_bucket_size 128; as the first line inside the http { block of /etc/nginx/nginx.conf. In the site file it is refused as a duplicate.
  4. Test it from your own computer. Without the key you should get 401; with it, the list of voices: 
    curl -s -o /dev/null -w "%{http_code}\n" https://tts.example.com/v1/audio/voices
curl -s -H "Authorization: Bearer YOUR_KEY" https://tts.example.com/v1/audio/voices
  5. In Aloud: address https://tts.example.com/v1, and paste the key into Key, without the word Bearer.

Aloud keeps the key in your browser on that device, sends it only to that server, and never puts it in a backup file. access_log off above keeps nginx from logging requests; the speech servers do not keep the text either.

If it doesn't connect

Aloud saysWhat to do
Can't reachIs the server running (docker ps)? Does the address end in /v1, with the right port? From a phone: is it on the same Wi-Fi, or on Tailscale? Is a firewall in the way?
asks for a keyThe server wants a key: paste it into Key and connect again.
refused the keyThe key is wrong. Paste it again, without "Bearer" and without spaces.
only over https://The address is on the internet. Put the server behind https as above, or use its address on your network or on Tailscale.
may not send textThe permission was taken back, in your browser's settings or by restoring a backup on another device. Press Connect again.

The voice reads the wrong language. A Phonon server reads the one language it was started with, and Aloud takes its voices to be English. Start it with PTTS_LANG=en, and let Aloud's own voices read other languages.

To stop using it, press Remove server in the Custom tab. Aloud forgets the address and the key, gives the permission back, and returns to its built-in voices.

Privacy

With a server set up, the text of each sentence being read goes to the address you entered, and only there. Nothing goes to Aloud, which has no server of its own. The privacy policy has the details.
